Target: WCAG 2.2 AA. Read-only audit: no `src/` edits by this agent. Each finding names the owning file so the lead can route it.
Scripts: `scripts/frontend-audit/tmp/a11y/` (throwaway, not part of the app). Summary: `docs/frontend/ACCESSIBILITY_AUDIT.md`.

## A11Y-1: Planner day chips and "Add meal" buttons fail Label in Name
- Severity: P2
- Route / component / file:line: `/planner`, `src/pages/Planning.tsx:150-160` (day chip), `src/pages/Planning.tsx:257-270` (add-meal)
- Defect (what a user sees): The visible text is "Mon 5" and "Add meal", but the accessible names are "Monday 5 October, 0 meals planned" and "Add breakfast on 2026-10-11". Speech-control users who say the visible label ("Add meal", "Mon") cannot activate the control. The add-meal names also read the ISO date aloud. The selected day uses `aria-current="true"`, which announces a location, not a selection.
- Root cause: `aria-label` replaces the visible text. The visible text is also `aria-hidden` on the day chip, so it is not in the name at all.
- Fix: Keep the visible text in the name. For example `aria-label` "Monday 5 October, 0 meals planned" should start with "Mon 5" or be built from the visible text plus a visually hidden suffix (`<span class="sr-only">, 0 meals planned</span>`). Use `aria-pressed` or `aria-selected` in a `role="tablist"` group for the selected day. Keep "Add meal" in the name, e.g. `Add meal for breakfast, Monday 5 October`.
- Needs other owner: planning (Planning.tsx) for the markup change. The `.sr-only` utility is shared; confirm it exists in the design-system CSS.
- Verification: `scripts/frontend-audit/tmp/a11y/extra.mjs` (axe `label-content-name-mismatch`, 375 and 1440, `/planner`): 7 day chips and 28 add-meal buttons flagged. Result before fix: FAIL.
- Status: OPEN

## A11Y-2: Cooking timer duration label does not match the accessible name
- Severity: P2
- Route / component / file:line: `/cook/<slug>` after "Begin cooking", `src/components/CookingTimer.tsx:171-174`
- Defect (what a user sees): The visible label reads "Timer duration", but `aria-label="Timer minutes"` overrides the `<label>` text. Voice-control users saying "Timer duration" cannot target the input.
- Root cause: The `aria-label` is redundant with the `htmlFor` label and conflicts with it.
- Fix: Delete `aria-label="Timer minutes"` so the `<label htmlFor="cooking-timer-minutes">` supplies the name. Optional: drop `aria-disabled` on the reset button and keep the native `disabled` only.
- Needs other owner: cookmode: `src/components/CookingTimer.tsx` (delete one attribute).
- Verification: `planner320.mjs` (second print): `ariaLabel: "Timer minutes"`, `labelText: "Timer duration"`. Result: FAIL.
- Status: OPEN

## A11Y-3: Quick-filter group uses aria-label on a plain div
- Severity: P2
- Route / component / file:line: `/explore`, `/favourites`, `src/pages/Explorer.tsx:236`
- Defect (what a user sees): Screen readers may ignore the "Quick recipe filters" name because a `div` with no role does not support `aria-label`. axe reports `aria-prohibited-attr` (serious) for the node, under "incomplete" (needs review).
- Root cause: Missing role on the wrapper.
- Fix: `<div className="quick-filters" role="group" aria-label="Quick recipe filters">`.
- Needs other owner: explorer: `src/pages/Explorer.tsx:236`.
- Verification: `keyboard.mjs` and `extra.mjs`, `aria-prohibited-attr` on `.quick-filters` at 375 and 1440. Result: needs review, FAIL on rerun.
- Status: OPEN (re-check: `quick-filters` still has no role)
- Note: `RecipeDetail.tsx` rating control had the same pattern. It now carries `role="group"` (RecipeDetail.tsx:578-581). Re-check on the next run.

## A11Y-4: Recipe card heart changes its name and also sets aria-pressed
- Severity: P2
- Route / component / file:line: `/`, `/explore`, `/favourites`, card in `src/components/UI.tsx:146-158`
- Defect (what a user sees): The name flips between "Save <title>" and "Unsave <title>", and `aria-pressed` also toggles. Screen readers announce both, e.g. "Unsave Crisp bone-in chicken thighs, toggle button, pressed". The name and state contradict each other.
- Root cause: Toggle buttons should keep a constant name and expose state through `aria-pressed`.
- Fix: `aria-label={\`Save ${recipe.title}\`}` with `aria-pressed`. Keep the heart icon and the `is-favourite` class for the visual state.
- Needs other owner: shell: `src/components/UI.tsx` (RecipeCard). Note: `UI.tsx` changed on disk during this audit. Line numbers may shift.
- Verification: `dynamic.mjs` / probe: card heart `aria-pressed` present, name switches with state. Result: FAIL (design-level, not caught by axe).
- Status: FIXED-VERIFIED (shell, UI.tsx:147-149). Re-check: `recheck.mjs` shows a constant name "Save <title> to favourites" with `aria-pressed` flipping true/false.

## A11Y-5: "Mark as tried" flips its name and keeps aria-pressed
- Severity: P2
- Route / component / file:line: `/recipe/<slug>`, `src/pages/RecipeDetail.tsx:328-336`
- Defect (what a user sees): Name becomes "Tried · undo" when pressed and "Mark as tried" when not. With `aria-pressed="true"` the reader says "Tried · undo, toggle button, pressed", which contradicts itself. Probe confirmed: name "Tried · undo", `aria-pressed="true"`.
- Root cause: Same as A11Y-4.
- Fix: Constant name "Mark as tried" with `aria-pressed`. Put the undo hint in the visible text or a `title`, and keep the toast "Tried status updated. You can undo this any time." (it is already a live status).
- Needs other owner: recipe: `src/pages/RecipeDetail.tsx:328-336`.
- Verification: `populate.mjs` / `verify-state.mjs` output "tried pressed true" plus probe name "Tried · undo". Result: FAIL.
- Status: OPEN

## A11Y-6: "Save recipe" button has no pressed state, while the card heart does
- Severity: P3
- Route / component / file:line: `/recipe/<slug>`, `src/pages/RecipeDetail.tsx:240-244`
- Defect (what a user sees): The name changes from "Save recipe" to "Saved" with no `aria-pressed`. Screen readers hear a plain button whose name says the state. The card heart uses a different pattern (see A11Y-4). Inconsistent, but understandable.
- Root cause: Inconsistent toggle pattern across the app.
- Fix: Constant name "Save recipe" with `aria-pressed={state?.favourite}`, and keep the visible "Saved" text as is.
- Needs other owner: recipe: `src/pages/RecipeDetail.tsx:240-244`.
- Status: FIXED-UNVERIFIED (recipe). `aria-pressed` is now present on the Save button (`recheck.mjs`: "true" on a saved recipe). Constant name not separately confirmed.

## A11Y-7: Back links are 19 px tall
- Severity: P2
- Route / component / file:line: `/recipe/<slug>` `src/pages/RecipeDetail.tsx:219`; `/cook/<slug>` `src/pages/CookMode.tsx:279`; CSS `src/styles.css:986-993` (`.back-link`)
- Defect (what a user sees): "Back to the kitchen" is a 132 x 19 px link at 375 px. WCAG 2.5.8 (target size minimum) needs 24 x 24 CSS px. The text is 12 px, the smallest size in the app.
- Root cause: `.back-link` has no min-height or padding, so the hit area is the text line box.
- Fix: `.back-link { min-height: 24px; padding-block: 4px; }` (44 px preferred). Consider `font-size: 14px` to meet the design system's text floor.
- Needs other owner: designsystem: `src/styles.css` (`.back-link` is a shared page-link primitive); recipe and cookmode own the markup.
- Verification: `final-checks.mjs` "ELEMENTS UNDER 24x24" list, 375 and 1440, light and dark. Result: FAIL.
- Status: FIXED-VERIFIED (designsystem, `.back-link` now 44 px tall; `recheck.mjs`). Cookmode back-link not separately measured.

## A11Y-8: Recipe title links in cards are 17 px tall

## A11Y-9: Offline and update notices are not announced
- Severity: P2
- Route / component / file:line: `src/App.tsx:326-337` (`.notice` for offline, and the service-worker "update ready" notice)
- Defect (what a user sees): When the device goes offline, or an update becomes ready, a banner appears in the main column. Nothing is announced to screen-reader users. Settings and Planner notices are fine.
- Root cause: The App notices are plain `div`s without `role="status"`.
- Fix: `<div className="notice" role="status">` for both. The "Update now" button stays inside the status region.
- Needs other owner: shell: `src/App.tsx:327` and `:333`.
- Verification: static read. Result: FAIL by WCAG 4.1.3 (status messages), not run live.
- Status: OPEN

## A11Y-10: Required-field errors in add-to-plan, shopping and journal depend on the browser bubble
- Severity: P3
- Route / component / file:line: shopping "Add an item" (`src/pages/Planning.tsx:~540-560`); recipe "Add to meal plan" (`src/pages/RecipeDetail.tsx` form near line 60-116); journal "Log a cook" (`src/components/SessionForm.tsx`)
- Defect (what a user sees): Submitting an empty shopping item shows the native validation bubble only. There is no in-page message, no `aria-invalid`, and no `aria-describedby`. The custom recipe form is the good example: 16 fields flagged with `aria-invalid` and `aria-describedby`, plus a summary `role="alert"`.
- Root cause: Native `required` only.
- Fix: Reuse the CustomRecipes pattern (aria-invalid, describedby, role=alert summary, focus first invalid field) in the three forms.
- Needs other owner: planning (shopping form), recipe (plan form), journal (SessionForm.tsx).
- Verification: `dynamic.mjs`: "shopping empty submit invalid: []". Result: P3 gap.
- Status: OPEN

## A11Y-12: Explicit items confirmed passing (no owner action)
- Recorded so the owners do not re-audit them.
- Heading order: exactly one `h1` per route, no skipped levels (13 routes, light).
- Landmarks: `main` (one), `nav` (main nav, quick nav, mobile menu), `header` and `footer`.
- Skip link: first Tab stop, Enter moves focus to `#main`.

- Dialogs (Shopping add, Journal log, Custom recipe, Planner day add, recipe add-to-plan, mobile menu): Escape closes each one, focus returns to the trigger. The mobile menu's close button and "Open navigation" restore focus correctly.

- Reduced motion: `src/styles.css:2769` and `src/styles/cook-mode.css:748` disable animations and transitions.
- Dark theme: `data-theme` follows `prefers-color-scheme` (checked), and axe passes in both themes.

- Cooking timer completion: `<p class="cook-timer-status" role="status">` changes to "Time to check your food…" when the timer finishes. Verified with a 61 s run. The countdown itself is `aria-live="off"`, so it does not spam.
- Explorer result count: `aria-live="polite"`.
- Dashboard and shopping progress bars have accessible names.
- Non-colour status: "Tried ✓" text on cards, line-through plus checkbox on shopping rows, heart fill plus `aria-pressed`.
